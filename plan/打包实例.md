## 打包
打包分为两种，一是命令行操作，另一种是GUI界面操作，首先完成命令行操作的实现

**打包动作只能对已注册的实例实施**

一般来说，实例主要有5部分组成
1. 配置文件——config文件夹 位于`<实例目录>/<实例种类，如MaiBot>/config`
2. 用户数据——data文件夹 位于`<实例目录>/<实例种类，如MaiBot>/data`
3. 环境文件夹——venv文件夹 位于`<实例目录>/<实例种类，如MaiBot>/<venv,.env,.venv诸如此类>`
4. 源码部分——`<实例目录>/<实例种类，如MaiBot>/` 下除上述两个文件夹以外的所有内容
5. 组件部分——`<实例目录>/<除实例种类文件夹外的所有文件及文件夹，如NapCat，venv也可能会放在这里>`
6. 插件部分——`<实例目录>/<实例种类，如MaiBot>/plugins`

### 默认策略

默认除了虚拟环境，我们会全部打包，使用以下命令
```bash
mcsb -o <实例序列号> 
```
这条命令会将除虚拟环境外的所有内容压缩并编码为iso文件，然后将扩展名替换为`.mcsins`,最后输出到与实例目录的**同级目录**下。最终命名为`<实例序列号>.mcsins`

### 自定义策略
当`mcsb`检测到 `-o`（等同于`output`）参数时，会进入打包模式。此时在**实例序列号后**添加一个`-f`（等同于`filter`）参数，该参数是允许自定义打包策略的，即允许用户指定打包的目录，以及指定打包的组件。

允许的参数有：
1. `!data`: 禁止打包data文件夹
2. `!config`: 禁止打包config文件夹
3. `!components`: 禁止打包任何组件文件夹或文件
4. `!src`: 禁止打包源码部分
5. `!plugins`: 禁止打包插件部分
6. `!venv`: 禁止打包venv文件夹
7. `!+venv`: 这里不同于往常，这是打包venv文件夹的命令，因为虚拟环境默认不会打包，所以需要打包的话加上这个参数
8. `--c{<实例项目目录下的任意文件或文件夹名，仅当前目录>}`这个参数是用来指定要打包的组件的，该优先级低于`!components`，并且是强匹配，若匹配失败，则不会打包
9. `@components`当用户忘记实例目录下有什么组件的时候，用户可以使用这个参数来查看所有组件，该参数会自动搜索实例目录下的所有组件文件夹，列出表格，然后你可以选择要打包的组件，相当于在**实例目录**中运行`ls`命令，但是不会显示实例本体的文件夹。
10. `--p{<插件文件夹名>}`这个参数是用来指定要打包的组件的，该优先级低于`!plugins`，并且是强匹配，若匹配失败，则不会打包
11. `@plugins`当用户忘记实例目录下有什么插件的时候，用户可以使用这个参数来查看所有插件，该参数会自动搜索实例目录下的所有插件**文件夹**，列出表格，然后你可以选择要打包的插件，相当于在**<实例目录>/<plugins>**中运行`ls`命令，但不显示文件。
12. 如果想要自定义导出位置，可以使用`-s`（等同于`site`）参数指定导出位置，默认导出位置为与实例目录同级目录下，文件名为`<任意名字，默认为实例序列号>.mcsins`，如果位置中没有标明名字（一个目录），则以序列号命名。
13. `-des` `description`用于编辑打包文件的描述，你可以使用json格式来编辑md格式的描述（比如换行符是\n），或直接连接到一个.md文件。

比如

```bash
mcsb -o test filter !data,!src,!componetents --p{MCPServers,ImaAPI} -s "D:\mcsins\test1.mcsins"
```
这段命令会打包除data文件夹、源码部分、所有组件文件夹、所有插件文件夹以外的所有内容，并指定导出位置为D:\mcsins\test1.mcsins
```bash
mcsb output abc,def -f @components --p{ImaAPI,MCPServers}
```
这段命令会打包“abc”、“def”这两个实例，查看组件文件夹，并打包“ImaAPI”、“MCPServers”两个插件文件夹。
> 注意：如果同时打包多个实例并使用的`-s`参数，那么最好每个实例的导出位置不同，如果只指定一个导出位置，那么导出的实例名称会按顺序依次为`<名字>.mcsins`、`<名字 (1)>.mcsins`、`<名字 (2)>.mcsins`...这样命名。如果位置中没有标明名字（一个目录），则以各自的序列号命名。

### 元数据

在压缩完成的iso文件中，会添加一个名为`meta.json`的文件，该文件包含以下字段：

```json
{
  "meta": {
    "name": "实例的名字",
    "serial": "实例的序列号",
    "author": "实例的作者",
    "mail": "作者的邮箱",
    "account": "作者的GitHub账户URL",
    "time": "打包的时间",
    "type": "实例的类型",
    "version": "打包的版本",
    "description": "实例的描述",
    "components": [
      "组件1",
      "组件2",
      "组件3"
    ],
    "plugins": [
      "插件1",
      "插件2",
      "插件3"
    ],
    "pack-source": "打包来源，如MaiCoreStart"
  }
}
```
用于标识打包信息。

## 导入

使用命令`mcsb import <文件名.mcsins>`或`mcsb -in <文件名.mcsins>`
显示实例信息，用rich渲染，**这里要求支持 .md 格式渲染**，并询问是否确定导入，就在当前文件夹下。

可以在后面添加`-s`参数指定导入位置，默认导入位置为当前目录下。

如
```bash
mcsb import test.mcsins -s "D:\mcsins"
```
最终的文件夹应该是D:\mcsins\test\<实例名称>\......
